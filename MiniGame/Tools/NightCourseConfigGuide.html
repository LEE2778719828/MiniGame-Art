NightCourse 配置数据流与 UE 资产索引

这页只描述当前 canonical Atom 管线：策划配置规则，艺术配置 Atom BP， DA_Course 负责把两者和运行入口接起来。页面不会自动保存 UE 资产。

1. 一条关卡如何生成

先记住这条关系：地图只负责入口，DA_Course 负责汇总，DA_Rules 负责动作队列，DA_Atoms 负责美术原子。

入口 L_Night_G1 选择地图 / PIE
启动 GameMode 指定 DefaultPawn、Host、CourseConfig
汇总 DA_Course 玩法数值、规则、Atom 库、分支规则
策划 DA_Rules Seed + 总数 + 加权 BaseRoute/BranchRoutes
美术 DA_Atoms AtomKey → Atom BP；Entry/Exit/落脚点/桥/怪
组合 CourseDirector 校验、按 Seed 选 Atom、拼接、生成桥与判定
运行 Pawn / Host / HUD Q/E 判定、岔路、成功失败和调试通知
重要：相邻 Atom 的衔接是长距离 Jump，使用 DA_Atoms.TransitionJumpGapCm， 不会自动在两个 Atom 之间生成一座桥。Atom 内部的桥和怪属于 Atom BP 的视觉配置。

2. 推荐配置顺序

  1. 先做 Atom BP

    在 Atom BP 中摆好 Entry、Exit、落脚点，以及每个落脚点的桥/怪视觉。 一个动作数组长度为 N 时，Atom 应有 N+1 个有效落脚点。

  2. 登记 Atom 库

    在 DA_Atoms.AtomMap 中用清晰的字符串 Key 指向 Atom BP；开启 bEnabled， 设置跨 Atom 的长距离 Jump 间距。

  3. 写策划规则

    在 DA_Rules 中设置 BaseAtomCount，并写 BaseRoute 模板池；A/B/C 分支设置各自的 TargetAtomCount。每个模板填写 AtomKey + Actions + Weight。 AtomKey 留空并开启 bAutoSelectAtomKeys，运行时按有效 Seed 确定性选择。

  4. 汇总到 DA_Course

    将 AtomRoute=DA_Atoms、CourseRuleData=DA_Rules、 RouteRules=DA_RouteRules、HeroClass=BP_NightHero 绑定到同一个课程配置。

  5. 绑定运行入口

    在 BP_NightCourseGameMode.CourseConfig 和关卡中的 BP_NightCourseHost.Config 都指定 DA_Course。 GameMode 是运行时权威来源，Host 绑定便于编辑器预览。

  6. 校验再 PIE

    手动保存并 Compile 相关 BP/DA 后，运行 Night.Course.Validate， 再执行 PIE。若需要看状态，使用 Night.Course.Dump。

3. UE 资产索引

路径就是 UE Content Browser 的对象路径。点击“复制路径”后可粘贴到 Content Browser 搜索框、 DataAsset 引用槽或蓝图资产引用槽。

关于“直接打开”：UE 本身没有原生的浏览器资产 URL 协议。本页的“尝试打开 UE”只在本机安装并配置 Hermes / UnrealHyperlink 一类插件时生效；未配置时请使用“复制路径”。这不会改变 UE 资产，也不会自动保存。

4. 最小 canonical Rule JSON

将下面 JSON 复制到 DA_Rules.EditorJson，再在 UE 中点击 Import Editor Json。Route 是模板池，按 Weight 生成目标数量； 每个 Atom 的 Actions 只描述判定，不描述网格和位置。

若不填写 baseAtomCount 或 targetAtomCount，C++ 会兼容旧格式， 使用对应模板数组长度；启用岔路时 forkAfterBaseAtomIndex 是岔口前实际生成的基础 Atom 数。

动作与 Atom 约束：Jump、Kill 是当前工具推荐写法； 旧别名 Hazard、Enemy 仅用于兼容输入。显式填 Key 时，Key 必须存在于 DA_Atoms.AtomMap，否则建议留空交给 Seed 选择。

5. 运行前检查

  • 打开 L_Night_G1，确认使用 BP_NightCourseGameMode。
  • GameMode 的 CourseConfig 指向 DA_Course。
  • 关卡 Host 的 Config 指向同一个 DA_Course。
  • DA_Rules 已启用，Seed 与队列有效。
  • DA_Atoms 已启用，AtomMap 中的 BP 均能加载。
  • 每个 Atom 的落脚点数量 = 对应 Actions 数量 + 1。
  • DA_RouteRules 有实际启用分支的 A/B/C 行。
  • 相关 BP/DA 已由人工 Compile、Save，未依赖 HTML 自动写盘。
  • 控制台执行 Night.Course.Validate 无错误。

6. 运行时数据流细节

1. GameMode.BeginPlay 读取 CourseConfig；若关卡已有 Host，则把 GameMode 的配置作为运行时 Config。
2. Host.StartCourse 绑定玩家 Pawn / Feel / Director，并触发课程启动；缺 canonical 引用直接失败。
3. Director.BuildAtomRouteCourse 读总数和加权模板池；按 Seed 生成 BaseRoute，达到 Fork 后从 BranchRoutes 取目标数量并继续加权生成。
4. Atom 拼接 前一 Atom 的 Exit 对齐后一 Atom 的 Entry；Atom 之间使用 TransitionJumpGapCm 的 Jump。
5. 视觉与判定 Atom BP 提供视觉绑定；Director 生成 gameplay carrier，并按落脚点顺序绑定 Actions。
6. 结果接口 成功/失败由 Host 的 OnNightSucceeded、OnNightFailed、OnNightFinished 和 Debug 消息输出。
角色与摄像机：BP_NightCoursePawn 是实际运行 Pawn；BP_NightHero 通过 DA_Course.HeroClass 提供角色视觉配置。摄像机组件的编辑应优先在实际运行 Pawn 蓝图中完成。
