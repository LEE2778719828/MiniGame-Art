NightCourse 快速配置指南

按 DA_Course → DA_Rules → DA_Atoms → DA_RouteRules → DT_GameStages 的顺序完成最少配置。 运行时路线由 Day 传入，M01-M05 掉落由 DA_Course 固定映射。页面不会自动保存 UE 资产。

1. 一条关卡如何生成

先记住这条关系：地图只负责入口，DA_Course 负责汇总，DA_Rules 负责动作队列，DA_Atoms 负责美术原子。

入口 L_Night_G1_ForkTest 选择地图 / PIE
启动 GameMode 指定 DefaultPawn、Host、CourseConfig
汇总 DA_Course 玩法数值、规则、Atom 库、分支规则、房屋/杆子配置
策划 DA_Rules Seed + RouteModes + BranchRoutes
美术 DA_Atoms AtomKey → Atom BP；Entry/Exit/落脚点/桥与临时预览
组合 CourseDirector 校验、按 Seed 选 Atom、拼接、生成桥与判定
运行 Pawn / Host / HUD Q/E 判定、岔路、成功失败和调试通知
重要：相邻 Atom 的衔接是长距离 Jump，使用 DA_Atoms.TransitionJumpGapCm， 不会自动在两个 Atom 之间生成一座桥。桥由 Atom BP 配置，敌人运行时 Blueprint 统一由 DA_Course.FoeActorMap 决定；Atom 只保留临时预览。

2. 推荐配置顺序

  1. 先做 Atom BP

    在 Atom BP 中摆好 Entry、Exit、落脚点和桥；如需对准位置， 可在落脚点填写 Temporary Preview Prefab，该引用不会进入运行时。 一个动作数组长度为 N 时，Atom 应有 N+1 个有效落脚点。

  2. 登记 Atom 库

    在 DA_Atoms.AtomMap 中用清晰的字符串 Key 指向 Atom BP；开启 bEnabled， 设置跨 Atom 的长距离 Jump 间距。

  3. 写策划规则

    在 DA_Rules.RouteModes[A/B/C] 中设置主段模板池；每个模式填写 TargetAtomCount 和 Atoms。A/B/C 分支设置各自 BranchRoutes[].TargetAtomCount。每个模板填写 AtomKey + Actions + Weight。 AtomKey 留空并开启 bAutoSelectAtomKeys，运行时按有效 Seed 确定性选择。

  4. 汇总到 DA_Course

    将 AtomRoute=DA_Atoms、CourseRuleData=DA_Rules、 RouteRules=DA_RouteRules、HeroClass=BP_NightHero 绑定到同一个课程配置， 并在 FoeActorMap 中为每个 EFoeId 指定一个敌人 BP； 在 FoeDropMap 中为 M01-M05 各绑定一个食材 ID，数量使用 DefaultDropCount； 按需启用 HouseRoadside / PoleRoadside 并填入道路装饰 BP 池。 开启岔路时，在 ForkAtomMap 中分别填写 AB、AC、BC 对应的 ANightCourseForkAtomActor 组合 Blueprint。

  5. 配置 Day 驱动模式

    在 DT_GameStages 每一行设置 DefaultRoute=A/B/C 与 ForkPair=AB/AC/BC。默认使用 A + AB；这里的值会覆盖 Night 运行时预览设置。

  6. 绑定运行入口

    在 BP_NightCourseGameMode.CourseConfig 和关卡中的 BP_NightCourseHost.Config 都指定 DA_Course。 GameMode 是运行时权威来源，Host 绑定便于编辑器预览。

  7. 校验再 PIE

    手动保存并 Compile 相关 BP/DA 后，运行 Night.Course.Validate， 再执行 PIE。若需要看状态，使用 Night.Course.Dump。
唯一正式入口：L_Night_G1_ForkTest 使用 BP_NightCourseGameMode、BP_NightCourseHost 和 canonical DA_Course。旧测试关卡与测试 DA 已从工程清理。

3. 道路两侧装饰

道路装饰由 CourseDirector 根据已组合的石头和桥在运行时生成； Host 预览整条道路，Atom 只提供单段对位预览。

DA_Course 配置

  • HouseRoadside 和 PoleRoadside 是独立配置。
  • BlueprintPool 支持多个 ANightRoadsideSegmentActor 子类； 每项 Weight 控制确定性随机选择。
  • SpacingCm 是 End 到下一个 Start 的间距；房屋使用 0 保持连续。
  • LeftBridgeOffsetCm / RightBridgeOffsetCm 是左右偏移； 房屋以路线起点的世界 Y 为基准，杆子以道路/桥中心线为基准。
  • 房屋沿世界固定 X 轴排列，不跟随 Atom 方向；右侧生成会自动使用 Y=-1 镜像。房屋统一使用路线第一个节点的世界 Z， 再叠加 ZOffsetCm；杆子仍按道路/桥方向和采样高度排列。

道路装饰 Blueprint

  • 父类：ANightRoadsideSegmentActor。
  • 移动 StartMarker 和 EndMarker 定义模块占用长度。
  • 网格、材质、动画和缩放由 Blueprint 自己控制，生成器不覆盖缩放。
  • 装饰默认无碰撞，不参与跳跃、攻击或石头判定。
特殊岔路 Blueprint：父类为 ANightCourseForkAtomActor， 必须保留 EntryAnchor、LeftExitAnchor 和 RightExitAnchor。桥面、路牌和其他装饰直接放在这个组合 Blueprint 内； PreviewForkPair 控制编辑器预览的 AB/AC/BC 类型，分支首 Atom 从所选出口加 BranchEntryGapCm 开始。
随机规则：房屋随机替换 Blueprint 但保持固定世界 X 轴上的标记首尾连续；杆子可以使用 RandomYawRangeDeg。随机流由课程 Seed、类别、左右侧和 RandomSeedOffset 派生，不影响 Atom、敌人或掉落随机。
Host LayoutBounds：必须开启 bEnforceLayoutBounds； LayoutBoundsExtent 表示以 Bounds 中心为原点的半尺寸。若当前 Atom 的 所有候选角度都越界，运行时会只沿世界 Y 轴把完整 Atom 平移到 Bounds 内， X/Z 保持原值，再继续生成。该应急平移可能改变当前 Atom 与前一段的过渡距离， 但可避免整局直接生成失败；若仅靠 Y 平移仍无法放入 Bounds 时会失败。

4. UE 资产索引

路径就是 UE Content Browser 的对象路径。点击“复制路径”后可粘贴到 Content Browser 搜索框、 DataAsset 引用槽或蓝图资产引用槽。

关于“直接打开”：UE 本身没有原生的浏览器资产 URL 协议。本页的“尝试打开 UE”只在本机安装并配置 Hermes / UnrealHyperlink 一类插件时生效；未配置时请使用“复制路径”。这不会改变 UE 资产，也不会自动保存。

5. 最小 canonical Rule JSON

将下面 JSON 复制到 DA_Rules.EditorJson，再在 UE 中点击 Import Editor Json。RouteModes/BranchRoutes 是模板池，按 Weight 生成目标数量； 每个 Atom 的 Actions 只描述判定，不描述网格和位置。

每个 RouteModes[A/B/C] 都有自己的目标数量和模板池； targetAtomCount=0 使用该池长度。旧 JSON 的 baseRoute/baseAtomCount 只在导入时一次性迁移到 routeModes.A， 导出不会再生成旧字段；forkAfterBaseAtomIndex 是岔口前实际生成的 Atom 数。

动作与 Atom 约束：Jump、Kill 是当前工具推荐写法； 旧别名 Hazard、Enemy 仅用于兼容输入。显式填 Key 时，Key 必须存在于 DA_Atoms.AtomMap，否则建议留空交给 Seed 选择。

6. 运行前检查

  • 打开 L_Night_G1_ForkTest，确认使用 BP_NightCourseGameMode。
  • GameMode 的 CourseConfig 指向 DA_Course。
  • 关卡 Host 的 Config 指向同一个 DA_Course。
  • DA_Course.FoeActorMap 的 M01–M05 都指向 NightCourseStoneActor 子类。
  • DA_Course.FoeDropMap 的 M01–M05 都绑定了非 None 食材 ID。
  • 岔路启用时，DA_Course.ForkAtomMap 的 AB/AC/BC 指向 ANightCourseForkAtomActor 子类，并已配置三组锚点。
  • 启用道路装饰时，HouseRoadside / PoleRoadside 的 BP 均为 ANightRoadsideSegmentActor 子类且 Start/End 标记有效。
  • DA_Rules 已启用，RouteModes[A/B/C] 与分支队列有效，Seed 已设置。
  • DT_GameStages 的 DefaultRoute=A/B/C 与 ForkPair=AB/AC/BC 已填写；默认 A + AB。
  • DA_Atoms 已启用，AtomMap 中的 BP 均能加载。
  • 每个 Atom 的落脚点数量 = 对应 Actions 数量 + 1。
  • DA_RouteRules 有实际启用分支的 A/B/C 行。
  • 相关 BP/DA 已由人工 Compile、Save，未依赖 HTML 自动写盘。
  • 控制台执行 Night.Course.Validate 无错误。

7. 运行时数据流细节

1. GameMode.BeginPlay 读取 CourseConfig；若关卡已有 Host，则把 GameMode 的配置作为运行时 Config。
2. Host.StartCourse 绑定玩家 Pawn / Feel / Director，并触发课程启动；缺 canonical 引用直接失败。
3. Director.BuildAtomRouteCourse 读取 Day 的 DefaultRoute，从 DA_Rules.RouteModes 生成岔路前主段；达到 Fork 后从 BranchRoutes 取目标数量并继续加权生成。
4. Atom 拼接 前一 Atom 的 Exit 对齐后一 Atom 的 Entry；普通 Atom 使用 TransitionJumpGapCm， 分支首 Atom 从特殊岔路的左右出口和 BranchEntryGapCm 连接。
5. 视觉与判定 Atom BP 提供桥与落点布局；Director 从 FoeActorMap 生成敌人、 从 ForkAtomMap 生成特殊岔路，并从 HouseRoadside / PoleRoadside 生成道路装饰；击杀奖励先按 FoeDropMap 取 ID， 数量按 DefaultDropCount，分支规则只调整节奏和倍率。
6. 结果接口 成功/失败由 Host 的 OnNightSucceeded、OnNightFailed、OnNightFinished 和 Debug 消息输出。
角色与摄像机：BP_NightCoursePawn 是实际运行 Pawn；BP_NightHero 通过 DA_Course.HeroClass 提供角色视觉配置。摄像机组件的编辑应优先在实际运行 Pawn 蓝图中完成。
