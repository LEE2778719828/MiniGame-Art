# R1 手感调参指南（DA_NightFeelTuning_Default）

调 R1 手感只需要动一个资产：

```
/Game/Night/Course/Data/DA_NightFeelTuning_Default
```

它挂在 `BP_NightCoursePawn` 的 `FeelStub.Tuning` 上，`BeginPlay` 时把表里的值套到 Feel 组件与主角。留空则退回代码默认值。

> **边界**：这张表只管 R1 的手感。起始魂量、关卡长度、石距、敌人分布归 R2 的 `DA_NightG1_T0`，不要在这里找。

---

## 一、三种改法

| 方式 | 怎么做 | 何时生效 | 适合 |
|---|---|---|---|
| **改资产**（推荐） | Content Browser 双击 `DA_NightFeelTuning_Default`，改完 Ctrl+S | 下次 Play | 定稿、进版本库 |
| **PIE 控制台现调** | `` ` `` 打开控制台，`Night.Feel.Set <项> <值>` | 立即 | 找手感、来回试 |
| **改表 + 热重载** | PIE 跑着时改资产，然后 `Night.Feel.Reload` | 立即 | 不想重开 PIE |

**不需要蓝图。** 这张表是 DataAsset，双击就是一个属性面板，和蓝图的 Details 面板长一样，但不用编译。

### 调参回路

```
Play → Night.Feel.Set Early 700    // 现调，立刻能感觉到
     → 反复试到满意
     → Night.Feel.Save             // 把当前运行值写回表并存盘
```

反过来，在 Content Browser 里改了表而 PIE 正开着：`Night.Feel.Reload`。

随时用 `Night.Feel.Status` 打印当前全部生效值，最后一行会显示挂的是哪张表。

## 二、参数逐条

### Grace 空档期 —— 「不按键多久开始掉魂」

| 参数 | 默认 | 含义 |
|---|---|---|
| `JumpWindowMs` | 280 | 跳跃落地后的宽限，这段时间内发呆不受罚 |
| `AttackWindowMs` | 260 | 斩击节点的宽限 |
| `bGraceWaitsForAnim` | true | 裁定 R-007：宽限从**动作播完之后**才起算 |
| `bUseTutorialWindows` | false | 教学放宽档总开关 |
| `TutorialJumpWindowMs` | 700 | 开教学档时替换上面两项 |
| `TutorialAttackWindowMs` | 520 | 同上 |

关键在于**窗口本身永不关闭**。这两个值不是「按晚了就失败」的截止线，按对任何时候都算命中。它们只决定「拖多久开始呼吸扣魂」。

`bGraceWaitsForAnim` 打开时，实际宽限 = 动画剩余时长 + 上面的 ms。这样斩击动画播 367ms 的时候不会因为动画长就被判发呆。关掉可以对比旧口径（落地即起算）。

**调大** → 节奏松、容错高；**调小** → 逼玩家连打，紧张感强。

### CatchUp 提前与追赶 —— 「按早了怎么办」

| 参数 | 默认 | 含义 |
|---|---|---|
| `EarlyAcceptMs` | 550 | 早于空档期这么多 ms 内的输入进缓存；更早则忽略（不扣魂、不断连） |
| `CatchUpPlayRate` | 1.5 | 命中缓存时，没走完的石间位移按此倍率加速播完 |
| `MaxCatchUpCompressMs` | 300 | 加速最多吃掉多少提前量，超出不再压缩 |
| `MaxBufferedInputs` | 3 | 缓存队列长度 |

这四个决定「连打顺不顺」。你之前反馈的「按 Q 后立刻按 E 有丝滑衔接」就是这套在起作用：提前的那一下不丢，存起来，同时把正在走的位移加速播完追上节奏。

- `EarlyAcceptMs` **调大** → 更宽容，抢拍也认；调小 → 必须踩点。
- `CatchUpPlayRate` **调大** → 追赶更急，动作会明显加速（动画倍率同步乘上去）；调到 1 = 不追赶，提前的输入要等位移走完才生效。
- `MaxCatchUpCompressMs` 是安全阀，防止提前太多导致动作快到看不清。

### Soul 扣魂

| 参数 | 默认 | 含义 |
|---|---|---|
| `BreathDecayPerSecond` | 0.55 | 空档期过后每秒掉多少魂，直到玩家行动（裁定 R-006 呼吸扣血） |
| `bEnableBreathDecay` | true | 关掉则发呆完全免费，仅调试用 |
| `SoulPenaltyHazard` | 7 | 在跳跃节点按错的扣魂 |
| `SoulPenaltyEnemy` | 5 | 在敌人节点按错的扣魂 |
| `HitInvulnMs` | 600 | 受罚后的无敌，期间不重复扣，防止连按被连罚 |

按裁定 R-006，只有两种情况掉魂：**按错**（一次性，取上面两个值）和**发呆**（持续，按 `BreathDecayPerSecond`）。按晚了不罚。

> **待收口**：Director 另有 `Config->WrongPenalty / MissPenalty` 一条路径，和 `SoulPenaltyHazard/Enemy` 覆盖范围重叠。改这里只影响 FeelStub 自判那条。需要和 R2 统一到一处。

### Anim 动作

| 参数 | 默认 | 含义 |
|---|---|---|
| `JumpAnimRate` | 1.0 | 跳跃动作基准倍率（<1 慢、>1 快） |
| `AttackAnimRate` | 1.0 | 斩击动作基准倍率 |
| `bAnimDrivenAdvance` | false | 开启后石间位移时长由动画锚点决定，不再用 R2 的 `AdvanceSpeed` |
| `JumpAnchorMs` | 266 | 跳跃落地帧（倍率 1.0 下），仅动画驱动模式生效 |
| `AttackAnchorMs` | 179 | 斩击接触帧，同上 |

倍率是**基准**，追赶加速在此之上再乘，所以改它不影响双时钟的压缩逻辑。

`bAnimDrivenAdvance` 是你提的那个方案：让位移时长等于动画到锚点的时长，这样倍率一改两者一起缩放、永远同步，一拍绝不会短于动作本身。代价是移动速度随石距浮动，石距不再影响节奏。默认关着，用 `Night.Anim.Drive 1` 开了对比过再决定。

### Debug 调试

| 参数 | 默认 | 含义 |
|---|---|---|
| `bLogJudge` | true | 每次判定写日志 |
| `bLogHudLines` | true | 屏显文字同时写日志（屏显一闪而过看不清时用） |

## 三、控制台速查

```
Night.Feel.Status                    打印当前全部生效值 + 挂的哪张表
Night.Feel.Set <项> <值>             现调，见下表
Night.Feel.Reload                    从表重新套用（改了表不想重开 PIE）
Night.Feel.Save                      把当前运行值写回表并存盘

Night.Anim.Status                    动作倍率与剩余时长
Night.Anim.Rate <Jump|Attack> <倍率>  改基准倍率
Night.Anim.Drive <0|1> [跳锚点] [斩锚点]  切动画驱动位移
Night.Anim.Mesh <抬升Z> [Yaw] [缩放]      现调主角落脚高度 / 朝向 / 大小
```

`Night.Feel.Set` 可用的项：

```
Jump  Attack  Tutorial  Early  CatchUp  MaxCompress
Hazard  Enemy  Invuln  Soul  Breath  BreathOn
LogHud  GraceWaitsAnim
```

`Soul` 是直接改当前魂量，用来把血量拨回满值继续测，不进表。

## 四、建议的调参顺序

1. **先修帧率**。当前 PIE 只有 15fps 左右，一帧就是 66ms，280ms 的空档期只有 4 帧。在这个帧率下十几毫秒的差别是感觉不到的，调再细都是白调。
2. **`AttackAnimRate` / `JumpAnimRate`** —— 先让动作看着顺眼，这是所有节奏的基准。
3. **`EarlyAcceptMs` + `CatchUpPlayRate`** —— 调连打的顺滑度，这一组对「爽」的贡献最大。
4. **`JumpWindowMs` / `AttackWindowMs`** —— 调整体松紧。
5. **`BreathDecayPerSecond`** —— 最后调惩罚力度，前面没定死之前调这个没有参照。

每改完一轮 `Night.Feel.Save` 落档，想留多套预设就复制资产另存。

## 五、改哪个资产（TA 对接面）

### 为什么 `BP_NightCoursePawn` 的事件图是空的

因为逻辑全在它的父类里。这是**代码蓝图**——父类是 C++ 的 `ANightCoursePawn`，输入、判定、位移、动画播放都在那边。蓝图这层只是个配置壳：Details 面板里的值会生效，事件图空着是故意的。

这么分是为了避免出现两套实现。逻辑一旦有一半在 C++ 一半在蓝图，改 C++ 的人不知道蓝图里还有一份，两边会静静地对不上。所以口径是：**蓝图只放数据，不放逻辑。**

需要新的可调项时告诉 R1，在 C++ 里加 `EditAnywhere` 暴露出来，比在蓝图里现搭一套快，也不会分叉。

### 改什么去哪里

| 想调 | 去哪 | 位置 |
|---|---|---|
| 手感数值（空档、缓存、扣魂） | `DA_NightFeelTuning_Default` | 见本文前四节 |
| 相机（臂长、偏移、角度、FOV） | `BP_NightCoursePawn` | 组件列表选 `SpringArm` / `Camera`，见下 |
| 动作 clip、倍率、锚点 | `BP_NightCoursePawn` | `Night｜Anim` |
| 主角落脚高度、朝向 | `BP_NightCoursePawn` | `Night｜Art` |
| 主角网格、材质、缩放 | `BP_NightHero` | `Night｜Art｜Visual` |
| 待机姿势、动作混合 | `ABP_NightHero` | AnimGraph |
| 斩击 / 跳跃的特效音效 | `Slash` / `Jump_noknife2` | 通知轨已标好时间点 |

### 相机改在组件上

打开 `BP_NightCoursePawn`，在左上角**组件列表**里选中 `SpringArm` 或 `Camera`，改它们自己的属性，所见即所得：

| 想调 | 选哪个组件 | 属性 | 当前值 |
|---|---|---|---|
| 镜头拉远拉近 | `SpringArm` | Target Arm Length | 620 |
| 俯角 | `SpringArm` | Rotation 的 Pitch | −28° |
| 画面偏移（角色不居中） | `SpringArm` | Socket Offset | (0, 55, 160) |
| 视野广窄 | `Camera` | Field Of View | 70 |

以前这几个值在 Details 面板的 `Night｜Camera` 分类下有一份**镜像属性**，开局会覆盖组件上的设置——在组件上改不生效也不报错。那三个属性已经删掉了，现在组件是唯一真相。

`SpringArm` 只继承 Yaw（`Inherit Pitch/Roll` 关着），所以转弯时镜头跟着摆，但角色的俯仰翻滚不会带歪画面。这三个开关别动。

还有四项开局仍会被代码强制写回，在组件上改**不生效**：`Do Collision Test`（关，否则桥面会把镜头顶开）、两个组件的 `Use Pawn Control Rotation`（关，本作没有视角输入）、以及 `Camera` 的那一组曝光覆盖（锁成手动，夜景不能自动适应）。要动这四项得改 C++ 的 `EnforceCameraInvariants`。

### 怎么保存、何时生效

**改 Details 面板上的数字（蓝图 / DataAsset / 动画通知轨）：`Ctrl+S` 就够，不用编译。**

确认落盘的标志：资产标签页上的星号消失，右下角变成「所有已保存」。只按 `Ctrl+S` 存的是**当前焦点那个资产**；同时改了好几个，用 `Ctrl+Shift+S` 全存。

| 改了什么 | 保存 | 何时看见 |
|---|---|---|
| `BP_NightHero` / `BP_NightCoursePawn` 的属性 | `Ctrl+S` | **停掉 PIE 再 Play**。开局会拷一次值，正在跑的那一局不会跟着变 |
| `DA_NightFeelTuning_Default` | `Ctrl+S` | 下次 Play；PIE 正开着则再打 `Night.Feel.Reload` |
| 动画上的 Notify | `Ctrl+S` | 下次 Play |
| `ABP_NightHero` 的图 | 先 **编译**（工具栏编译按钮），再 `Ctrl+S` | 下次 Play |

不要在 PIE 视口里点角色改 Details——那是这一局的实例，不写回蓝图，停掉就丢。始终打开 Content Browser 里的那个资产改。

控制台现调（`Night.Feel.Set`、`Night.Anim.Mesh`）立刻看得见，但**不写磁盘**。满意之后还是要回到对应资产改同一组数，再 `Ctrl+S`。手感表有捷径：`Night.Feel.Save` 会把当前运行值写回 `DA_NightFeelTuning_Default` 并存盘。缩放没有对应命令，PIE 里试完要把数填进 `BP_NightHero` 的 `HeroScale`。

### 两个坑

**`BP_NightHero` 只有五个属性会生效。** 它不是被 spawn 的 Pawn，只是个"外观配置载体"，开局由 `NightCourseHost::WireFeelFromPlayer` 把值拷到真 Pawn 上。拷的只有 `HeroSkeletalMesh`、`HeroStaticMesh`、`HeroMaterial`、`HeroScale`、`HeroPivotOffsetCm` 这五个。在它上面改相机、改动作倍率、改落脚偏移——**不报错，也不生效**。那些要改在 `BP_NightCoursePawn` 上。

同一类静默失效以前在相机上也有一份（镜像属性覆盖组件），已经消掉了，见上面「相机改在组件上」。

**`.uasset` 合不了。** 二进制资产没有三方合并，两个人同时改同一个就是丢一边的工作。动上面这些之前先说一声谁占哪个。

**试完值改回去，也要再存一次。** 存过一个试验值之后又在面板里改回原值（或者按撤销），那次回退同样要 `Ctrl+S`，否则盘上留着的还是试验值——现在 Play 用的是内存里的新值，看起来一切正常，重开编辑器才变回去。这种不一致 `git status` 只会显示资产被改过，看不出改成了什么。要确认改了什么值只能在编辑器里打开对比。

### 动画那边的硬约束

`ABP_NightHero` 的 TargetSkeleton 是 `SK_Hero_Skeleton`，建完即固定，改不了。交付里那个 `ABP_zhujue` 绑的是 `SK_zhujueSitting_Skeleton`，装不到我们的主角上，得在 `ABP_NightHero` 里做。

当前待机用的是 `Sitting`（坐姿），**是占位**——美术没交站立待机。补到之后换掉序列播放器那一个节点即可。

特效音效不需要动画蓝图：标记已经全部标好，在标记处放自执行型 Notify（`Play Sound` / `Play Niagara Effect`）就能直接出效果。

| 片段 | 标记 | 时间 | 用途 |
|---|---|---|---|
| `Slash` | `Contact` | 0.179s | 命中 |
| `Jump_noknife2` | `Takeoff` | 0.100s | 蹬地烟尘 |
| `Jump_noknife2` | `Land` | 0.266s | 落地 |
| `Jump_noknife2_fast` | `Takeoff` / `Land` | 0.064s / 0.167s | 快版备用，未启用 |
| `Slash_fast_Armature_Armature_kan` | `Contact` | 0.083s | 快版备用，未启用 |

这些时间是逐帧实测的（`Tools/ProbeAnimNotifyPoints.py`），和代码里的 `AttackAnchorMs` / `JumpAnchorMs` 同源，别改。

`Slash` 上 300ms 处武器手速度还有一个 1518cm/s 的峰，那是**收招回摆不是第二次命中**，在那儿放打击音会变成一刀两响。想做刀光用带时长的 Notify State，区间取 133–233ms。
